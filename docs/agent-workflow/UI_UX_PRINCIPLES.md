# UI/UX review principles

- Identify the user role, goal, entry point, exit path, device constraints, and copy that must remain unchanged before redesigning a screen.
- Map navigation and context first. Make the next action clear, preserve relevant state, and ensure Back, Cancel, browser history, and menu behavior agree.
- Reuse the current RETURNO type, spacing, color, control, and card patterns. Do not add decoration unless it supports hierarchy or grouping.
- Check default, hover, focus, pressed, loading, empty, validation, success, error, disabled, and permission states where applicable. Give specific recovery instructions and preserve recoverable form input.
- Use semantic controls, accessible names and labels, keyboard operation, visible focus, sufficient contrast, meaningful image alternatives, and reduced-motion support.
- Test realistic text lengths, content wrapping, image containment, touch interactions, and control sizes at narrow phone, tablet, and desktop widths. Do not infer device quality from shrinking a desktop screenshot.
- Inspect the rendered page and exercise its key interaction. Automated accessibility checks are evidence, not a complete accessibility review.
